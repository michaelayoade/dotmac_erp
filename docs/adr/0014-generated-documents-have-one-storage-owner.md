# ADR-0014 — Generated documents have one storage owner

- **Status:** Accepted
- **Date:** 2026-10-26
- **Decider:** Michael
- **Program slice:** ERP thin-client replacement, files close-out
- **Design:** `docs/architecture/generated-documents-files-cutover.md`

## Context

User uploads completed their move to `dotmac-files` on 2026-10-19
(#722–#747): every uploaded byte is staged through `prepare_upload` and
recorded in the module's tenant plane. Generated bytes were left behind
as "unclassified": template-generated documents, report instances and
async exports still write through the legacy `FileUploadService` to
ad-hoc S3 prefixes, and payslip PDFs are not stored at all — they are
re-rendered on every view and email.

Two storage owners for files is the exact condition the upload cutover
ended. Leaving generated documents on the legacy path would keep
`get_storage()` write paths, the legacy download branches in
`app/api/files.py`, and a second orphan/reconciliation story alive
indefinitely.

## Decision

1. **All four generated families** — payslips, template-generated
   documents, report instances, async exports — move to the
   `dotmac-files` tenant plane through the same seam as user uploads.
   No family keeps a legacy path as its endpoint.
2. **Payslip PDFs become immutable stored artifacts**, generated once at
   salary-slip posting (the emailed bytes are the stored bytes) and
   served from storage thereafter. A re-issue supersedes; it never
   overwrites. This is a deliberate behaviour change: a payslip is an
   issued financial record, and template or branding changes must not
   rewrite history.
3. Synchronous generate-and-stream responses that persist nothing
   today (inline small exports, invoice PDF rendering) stay unpersisted.
   Invoice artifacts are `dotmac-billing`'s concern, not this ADR's.
4. Retention deletion for reports/exports deletes the staged file with
   the owning row. Orphan reconciliation is the safety net, not the
   retention mechanism.

## Consequences

- `GeneratedDocument`, `ReportInstance` and `SalarySlip` gain file-id
  columns; `file_path` values freeze as the legacy record until the
  per-family backfills and legacy-branch deletions complete (the upload
  cutover's staged/legacy pattern, unchanged).
- The orphan-reconciliation reference view must learn each new column in
  the slice that introduces it.
- No `dotmac-files` module change is required at 0.1.0a7.
- Legacy storage retirement (the final `get_storage()` write-path
  deletion) is gated on this ADR's slices as well as the thirteen
  upload-family backfills.
